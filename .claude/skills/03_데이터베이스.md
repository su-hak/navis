# 03. 데이터베이스 설계 (TypeORM)

> **목적**: TypeORM을 사용한 Entity 설계, Index 최적화, Migration 전략

---

## 🗄️ TypeORM 기본 개념

### Entity란?
- DB 테이블과 1:1로 매핑되는 클래스
- `@Entity()` 데코레이터로 표시
- 각 필드는 `@Column()` 데코레이터로 정의

---

## 📋 핵심 Entity 패턴

### 1. User Entity (기본)
```typescript
import {
  Entity,
  PrimaryGeneratedColumn,
  Column,
  CreateDateColumn,
  UpdateDateColumn,
} from 'typeorm';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ type: 'varchar', length: 255, unique: true })
  email: string;

  @Column({ type: 'varchar', length: 255 })
  password: string;

  @Column({ type: 'varchar', length: 100 })
  name: string;

  @Column({ type: 'boolean', default: false, name: 'is_email_verified' })
  isEmailVerified: boolean;

  @Column({ type: 'datetime', nullable: true, name: 'email_verified_at' })
  emailVerifiedAt: Date | null;

  @CreateDateColumn({ name: 'created_at' })
  createdAt: Date;

  @UpdateDateColumn({ name: 'updated_at' })
  updatedAt: Date;
}
```

**핵심 포인트**:
- ✅ `uuid` 사용 (보안 강화)
- ✅ `snake_case` 컬럼명 (`name: 'is_email_verified'`)
- ✅ `CreateDateColumn`, `UpdateDateColumn` 자동 관리
- ✅ `nullable: true` 명시적 지정

### 3. Payment Entity
```typescript
import {
  Entity,
  PrimaryGeneratedColumn,
  Column,
  ManyToOne,
  CreateDateColumn,
  JoinColumn,
} from 'typeorm';
import { User } from './user.entity';

export type PaymentStatus = 'success' | 'failed' | 'cancelled';

@Entity('payments')
export class Payment {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @ManyToOne(() => User, { onDelete: 'CASCADE' })
  @JoinColumn({ name: 'user_id' })
  user: User;

  @Column({ type: 'varchar', length: 100 })
  tid: string; // 거래ID

  @Column({ type: 'varchar', length: 100 })
  orderId: string;

  @Column({ type: 'decimal', precision: 10, scale: 2 })
  amount: number;

  @Column({ type: 'enum', enum: ['success', 'failed', 'cancelled'] })
  status: PaymentStatus;

  @Column({ type: 'varchar', length: 500, nullable: true })
  failReason: string | null;

  @CreateDateColumn({ name: 'created_at' })
  createdAt: Date;
}
```

**핵심 포인트**:
- ✅ `@ManyToOne`으로 User와 관계 설정
- ✅ `onDelete: 'CASCADE'` → User 삭제 시 Payment도 삭제
- ✅ `decimal` 타입으로 금액 저장 (정확도)
- ✅ `enum` 타입으로 상태 제한

### 5. AB Test Event Entity (Index 포함)
```typescript
import {
  Entity,
  PrimaryGeneratedColumn,
  Column,
  CreateDateColumn,
  Index,
} from 'typeorm';

@Entity('ab_test_events')
@Index('idx_device_variant', ['deviceId', 'variant']) // 복합 인덱스
export class AbTestEvent {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ type: 'varchar', length: 255, name: 'device_id' })
  deviceId: string;

  @Column({ type: 'varchar', length: 1 })
  variant: string;

  @Column({ type: 'varchar', length: 50, name: 'event_type' })
  eventType: string;

  @Column({ type: 'json', nullable: true })
  metadata: any;

  @CreateDateColumn({ name: 'created_at' })
  createdAt: Date;
}
```

**핵심 포인트**:
- ✅ `@Index` 데코레이터로 복합 인덱스 생성
- ✅ 자주 조회되는 컬럼 조합에 인덱스 추가
- ✅ `json` 타입으로 유연한 메타데이터 저장

## 🔗 Relations (관계 설정)

### OneToMany 예시
```typescript
// user.entity.ts
@Entity('users')
export class User {
  // ...

  @OneToMany(() => Payment, (payment) => payment.user)
  payments: Payment[];

  @OneToMany(() => Sheet, (sheet) => sheet.user)
  sheets: Sheet[];
}
```

### ManyToOne 예시
```typescript
// payment.entity.ts
@Entity('payments')
export class Payment {
  // ...

  @ManyToOne(() => User, (user) => user.payments, { onDelete: 'CASCADE' })
  @JoinColumn({ name: 'user_id' })
  user: User;
}
```

### Eager vs Lazy Loading
```typescript
// Eager Loading (자동으로 관계 로드)
@ManyToOne(() => User, { eager: true })
user: User;

// Lazy Loading (필요할 때만 로드) - 기본값
@ManyToOne(() => User)
user: User;

// 사용 시
const payment = await this.paymentRepository.findOne({
  where: { id },
  relations: ['user'], // Lazy일 때 명시적으로 로드
});
```

## 📊 Index 최적화

### 단일 인덱스
```typescript
@Entity('users')
export class User {
  @Column({ type: 'varchar', length: 255, unique: true })
  @Index() // 단일 인덱스
  email: string;
}
```

### 복합 인덱스
```typescript
@Entity('ab_test_events')
@Index('idx_device_variant', ['deviceId', 'variant'])
@Index('idx_variant_eventType', ['variant', 'eventType'])
export class AbTestEvent {
  @Column({ name: 'device_id' })
  deviceId: string;

  @Column()
  variant: string;

  @Column({ name: 'event_type' })
  eventType: string;
}
```

### Index가 필요한 경우
- ✅ WHERE 절에 자주 사용되는 컬럼
- ✅ JOIN에 사용되는 컬럼
- ✅ ORDER BY에 사용되는 컬럼
- ✅ 외래키 (Foreign Key)

### Index를 피해야 하는 경우
- ❌ 거의 조회되지 않는 컬럼
- ❌ 변경이 빈번한 컬럼 (INSERT/UPDATE 성능 저하)
- ❌ 카디널리티가 낮은 컬럼 (예: boolean)

## 🔄 Migration 전략

### synchronize vs Migration

#### synchronize: true (개발 환경만)
```typescript
TypeOrmModule.forRoot({
  synchronize: process.env.NODE_ENV !== 'production',
})
```
- ✅ 개발 시 편리 (Entity 변경 시 자동으로 DB 스키마 변경)
- ❌ 프로덕션에서 사용 금지 (데이터 손실 위험)

#### Migration (프로덕션)
```bash
# Migration 생성
npm run typeorm migration:generate -- -n AddSubscriptionFields

# Migration 실행
npm run typeorm migration:run

# Migration 되돌리기
npm run typeorm migration:revert
```

### package.json에 스크립트 추가
```json
{
  "scripts": {
    "typeorm": "ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js",
    "migration:generate": "npm run typeorm migration:generate",
    "migration:run": "npm run typeorm migration:run",
    "migration:revert": "npm run typeorm migration:revert"
  }
}
```
